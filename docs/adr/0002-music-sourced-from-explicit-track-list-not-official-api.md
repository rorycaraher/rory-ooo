# Music tracks are sourced from an explicit track list, not SoundCloud's official API

Music tracks are listed via explicit per-track content stubs (`content/music/<slug>.md`, headless, holding a SoundCloud track URL plus a manually-entered release date); CI resolves title/description for each listed URL via SoundCloud's public, keyless `oembed` endpoint and writes them to a generated data file keyed by URL — the same shape as `data/projects.yaml`. We are not using SoundCloud's official API.

We made this choice because SoundCloud's official API now requires an Artist Pro subscription to register an app and obtain client credentials, and even with those credentials it would auto-enumerate "all public tracks" the same way GitHub's pinned-items feature auto-derived the Projects list — which [ADR-0001](./0001-projects-sourced-from-explicit-repo-list.md) already rejected, for the same reason: external platform state shouldn't drive what the site shows. `oembed` is public and keyless but only resolves metadata for a URL you already have, not a track listing, which keeps curation explicit. The trade-off is the same as ADR-0001's: adding a track is a manual step (create a stub with the track URL and date) rather than fully automatic, in exchange for explicit control and no dependency on an Artist Pro subscription.
